## Production Changes

**Metrics tab date-ambiguity UX fix (user-reported, Critical).** The
chart x-axis showed only time-of-day ("03:45:00 PM") at every range,
including 24h/7d where multiple calendar days collapse onto bare times
with no way to tell which day a point is from. Fixed with range-aware
axis labels (date-aware past 6h), always-absolute tooltip timestamps,
and a visible date-range banner whenever the chart's visible window
spans more than one calendar day. New `src/lib/chartTime.ts` module
(`formatAxisTick`, `formatTooltipTimestamp`, `getDateRangeLabel`), wired
into `MetricsDashboard.tsx`'s 6 chart tooltips. Verified via real
Chromium (Playwright, not just jsdom) against a live cluster and real
pod data, in addition to unit tests.

**Nested `<button>` accessibility fix (found incidentally during the
above, via browser console warnings).** `RecentResources.tsx`'s
section-toggle control wrapped a "Clear recent resources" `<button>`
inside another `<button>` — invalid HTML that breaks keyboard focus
order and, confirmed specifically via real Chromium (not jsdom, which
doesn't reproduce this), swallows the inner button's accessible name
into the outer control's. Fixed by converting the outer toggle to a
`role="button"` `div` with explicit `aria-label`, `tabIndex`, and
`onKeyDown` (Enter/Space) handling.

**GHCR image-visibility blocker (blocking the Helm chart release).**
`ghcr.io/kubilitics/kubilitics-backend` — the image the main Helm
chart's `values.yaml` points at — was both stale (the `docker-build.yml`
workflow's `push` trigger had been removed at some point after March
2026, leaving only `pull_request`, which never pushes, and
`workflow_dispatch`) and private. Fixed by manually triggering a fresh
`workflow_dispatch` build/publish and having the package's visibility
changed to public (confirmed via `gh api .../packages/container/.../
visibility` and a real anonymous `docker pull`, not just the GitHub UI,
which was initially showing a stale "public" state from an incomplete
visibility-change confirmation). `kubilitics-frontend`/`kubilitics-agent`
image visibility gaps were investigated and found not to block this
release — `kubilitics-frontend` is referenced only in CI test overrides,
not the deployable chart, and `kubilitics-agent` is a separate,
optional multi-cluster chart, not a main-chart dependency.

**Crash sweep, Task 13 (2 real bugs found via render-based testing, not
code reading).** This project's own established lesson — confirmed
again here — is that tsc-error/code-reading sweeps miss real crash
bugs; only actual React Testing Library renders with malformed/sparse
payloads reliably catch them:
- 35 list pages (159 call sites) accessed `resource.metadata.X` without
  a guard on a value typed as required but not actually guaranteed at
  runtime (a malformed list item crashes the whole page, not just that
  row). Fixed with `resource.metadata?.X` plus existing fallback
  conventions.
- `useHealthScore.ts` crashed when the backend's `/overview` response
  omitted `health` (used `!!overviewQuery.data` instead of
  `!!overviewQuery.data?.health`), instead of falling through to the
  hook's existing direct-K8s fallback path.

Both reverted and reconfirmed against the exact reported error before
being accepted as real (not assumed from the diff).
